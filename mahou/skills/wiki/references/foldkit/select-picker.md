# A select-like picker on Foldkit's Dialog

verified: 2026-11-23

Answers how to build a picker that behaves like a select (a field that shows the picked value and opens a searchable list) with Foldkit 0.170 and `@foldkit/ui` 0.170, how one component can open as a bottom sheet on the phone and as a dropdown under the field on the desktop, and which Foldkit lint rules shape its module layout.

## Knowledge

- No `@foldkit/ui` primitive is a select with a search field inside its panel. `Listbox` has a trigger button and an anchored panel, but the panel renders only its items, so a search input has no slot. `Combobox` makes the field itself the text box that filters as you type. `Select` wraps a native `<select>`.
- A select-like picker can be composed from `Dialog` plus the ARIA combobox pattern written by hand: the field is a `<button>` with `aria-haspopup="listbox"` and `aria-expanded`; the dialog holds a search `<input role="combobox">` with `aria-controls` pointing at a `<ul role="listbox">` and `aria-activedescendant` pointing at the active `<li role="option" aria-selected>`. `Dialog` supplies the backdrop, focus trap, Escape on the topmost dialog, return of focus to the field and background inertness.
- Give `Dialog.init` a `focusSelector` for the search input's id so focus lands in it on open. Focus arrives after the first paint, so a screenshot taken right after the click can still show focus elsewhere.
- Keep the picker's own state small: the `Dialog.Model`, the search text and the active index. The parent owns the picked value and passes it in; the picker reports `Picked`, `ChangedSearch` and `Opened` as out-messages, so a parent can run a server search (or load a first page on `Opened`) for lists it filters itself.
- Keyboard: `h.OnKeyDownPreventDefault` on the search input returns `Option.some(message)` for ArrowDown, ArrowUp and Enter and `Option.none()` for every other key, so typing still reaches the input. The view computes the next index and the value under Enter from the visible list, which keeps the update function free of the option list. Scroll the active option into view with a Command around `Dom.scrollIntoViewIfNotVisible(selector, { block: "nearest", when: "Commit" })`; `aria-activedescendant` does not scroll.
- `Dialog` opens through `Dom.showDialog`, which calls `show()` (not `showModal()`), positions the `<dialog>` fixed with a high z-index and is not in the top layer. A `position: fixed` panel inside it is laid out against the viewport, so CSS anchor positioning works: put `anchorName: "--<id>"` on the field and `positionAnchor: "--<id>"` on the panel with `h.Style` (one name per picker), and `top: anchor(bottom)`, `left: anchor(left)`, `minWidth: max(anchor-size(width), 220px)` and `positionTryFallbacks: flip-block` in the panel's styles. A media query switches the same panel to `left: 0; right: 0; bottom: 0; height: 50vh` with a scrim on the backdrop, which gives the bottom sheet on the phone and the dropdown on the desktop from one element. Checked in Chromium 149; a nested picker `<dialog>` inside an open sheet `<dialog>` anchors to a field inside that sheet.
- Escape closes only the topmost dialog. After a Vite hot-module reload restored a page with a sheet and a picker both open, Escape reached the sheet instead of the picker; a fresh load did not do this.
- `foldkit/no-child-message-construction-in-root` (`@foldkit/oxlint-plugin` 0.15) flags `Child.Message.X(...)` built anywhere except inside a function whose `h` parameter is typed `HtmlBuilder<Child.Message>` or inside `Submodel.defineView<ChildModel, ChildMessage, Inputs>`. A generic view that takes a parent `HtmlBuilder<Message>` and a `toMessage` mapper fails it. Write the picker's view with `Submodel.defineView` over the child Message, and give parents a thin wrapper that calls `h.submodel({ model, slotId, toParentMessage, view, viewInputs })`.
- Html built by the parent and handed into a child view must not dispatch parent Messages: the submodel maps every event inside it through `toParentMessage`, so a parent's button nested there would be wrapped as a child Message. Pass data (a notice text) instead of Html.
- `foldkit/got-prefix-requires-submodel-payload` accepts `GotX: { message: Ns.Message }` only as a member expression, so a Message union imported by its bare name fails. Export the child module's `Model`, `Message`, `OutMessage`, `init` and `update` and import it as a namespace (`import * as PickerKit from ...`). `eslint(no-redeclare)` then rejects a type with the same name as the value, so name the types `ModelValue`, `MessageValue`, `OutMessageValue`.
- `foldkit/got-wrapper-carries-only-routing` allows only `message`, `id` and keys ending in `Id` on a `Got*` wrapper. Several pickers per row are routed with `{ lineId, fieldId, message }`, where `fieldId` is a literal union naming the field.
