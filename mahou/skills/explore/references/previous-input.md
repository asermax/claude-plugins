# Opening with previous input

Previous input is earlier work on the change that the context includes: decisions already recorded, findings from an earlier investigation, a definition of the problem or the solution, a design, a proposal or its working notes, notes from a meeting. Build on it instead of starting from zero.

## Consolidating

Before laying anything out, gather every decision the input records into the settled set:

- Number each decision and name its source.
- Merge a decision that appears in more than one source into one line that names every source.
- Mark a decision that a later one replaced as replaced.
- Settle them without a confirmation round.

Group the rest of the input by topic. Keep the verified or asserted mark of each fact an earlier investigation recorded, and verify a fact again only when a question rests on it.

## Laying it out

Open with the settled set. Then give each topic in turn:

- The topic's content in full, not a summary, each item naming its source. Keep apart what the sources ask for, what the user decided that departs from them, and where they contradict each other or the user's direction.
- Its questions, as sub-items under the topic:
  - The questions that validate the details of the decisions settled in the topic: what a decision leaves unspecified, a case it does not cover, a term it uses that no source defines.
  - The questions the input leaves open: topics it lists as open, gaps between the sources, decisions that contradict each other.

Write each question with no preference. These questions are decisions waiting on the user, not proposals of where to look. The user answers them or asks their own question, and each answer is recorded like any other decision. When the user corrects a decision through a validation question, record the correction as a new decision that replaces it.
