# R2: S3 access, presigned URLs and pricing

verified: 2026-10-10

Answers whether code written for an S3-compatible bucket works against R2, how presigned URLs behave in a browser, how to serve SVG from a bucket safely, and what R2 costs. Distilled from documentation and from spikes that served audio and SVG to Chromium through presigned URLs.

## Knowledge

- boto3 works against the S3 API with `endpoint_url=https://<ACCOUNT_ID>.r2.cloudflarestorage.com` and `region_name="auto"`. From a Worker, `aws4fetch` (4 KiB gzipped) and `@aws-sdk/s3-request-presigner` (120 KiB gzipped, needs `nodejs_compat`) both sign URLs in workerd.
- S3 credentials for R2 come from an R2 API token created in the dashboard (R2, Manage API tokens); wrangler's OAuth login cannot create them.
- Presigned URLs support GET, HEAD, PUT and DELETE, expire from 1 second to 7 days, and work only on the `*.r2.cloudflarestorage.com` host, not on a custom domain. A presigned PUT needs no other authentication header, so a plain HTTP client can upload with the presigned URL alone; when `ContentType` is signed, the upload must send the same value or R2 answers `403 SignatureDoesNotMatch`. A single-part upload goes up to about 5 GiB.
- A Worker that answers with a 307 to a presigned GET works for `<audio src>`: Chromium played the audio from another origin, seeked, and R2 answered range requests with 206 and the right `Content-Range`. The spike tested only Chromium.
- An expired presigned URL stalls playback with no `error` event. The browser keeps using the resolved R2 URL for later range requests and never goes back to the Worker, so the Worker never mints a fresh URL; buffered audio keeps playing.
- `<audio src>` cannot send custom headers, so a route guarded by an API-key header cannot be the element's source.
- CORS: without the `crossorigin` attribute no CORS is needed. With it, playback worked only when the Worker's 307 carried `Access-Control-Allow-Origin: *` and the bucket's CORS rule allowed origin `*`; a rule for the page's origin alone failed.
- SVG served from R2: scripts and event handlers inside an SVG do not run when it is shown in `<img>`. They do run when the URL is opened in a tab and when the SVG is embedded with `<object>`, `<iframe>` or `<embed>`. They run in the bucket host's origin (`<bucket>.<account>.r2.cloudflarestorage.com`). Signing the URL with `response-content-type` of `text/plain` or `application/octet-stream`, or with `response-content-disposition=attachment`, stops execution in a tab; a stored `Content-Disposition: attachment` does too. R2 ignores `response-content-security-policy`, and neither stores nor returns CSP or `X-Content-Type-Options` set at upload time. Whether `<img>` still renders an SVG served as an attachment or with an overridden type is untested.
- A custom domain gives caching and access control through Access or WAF token authentication. `r2.dev` is rate-limited and meant for development only. From a Worker, an R2 binding is also available. Local development: see `local-dev`.
- Standard storage is $0.015 per GB-month with 10 GB-month free; Class A operations $4.50 per million with 1 million free a month, Class B $0.36 per million with 10 million free. Egress is free. Infrequent Access is $0.01 per GB-month, with higher operation prices, a $0.01/GB retrieval fee and a 30-day minimum.
