# Discovery mode

Used when `learn` is invoked without arguments.

1. **Recall the conversation.** Reread it end to end before judging any part of it. Where it has been compacted, work from what remains and say so. A summary keeps the decisions and drops the mechanics this skill exists to find, so name the gaps instead of filling them with a plausible reconstruction.

2. **Summarize the session back to the user, and stop there.** This is a deliverable in its own right, not a preamble.

   Write it as a chronological account in plain prose. Paragraphs group the blocks of work in the order they happened, with the decisions, reversals and corrections placed where they occurred. No headings, no dates, no numbered sections.

   Close with a separate **My take** section, in bullets. Each bullet is what stands out when the session is held against the plugin's existing skills and wiki. A procedure that ran ad hoc where a skill exists or none does, a step that lives only in session memory, a guardrail nothing enforced, a fact about a tool that had to be rediscovered, a correction the user has now made more than once. Read the skills and entries the session touched before writing it. Each bullet is an observation, not a proposal.

   Ask whether it matches what they remember. They were there. You are reconstructing. Iterate on the summary until it does.

3. **The user proposes what to keep.** Do not present a candidate list, and do not turn the take's bullets into proposals. They are raw material for the user's own picks. Answer questions about the take, then wait.

Continue with **Drafting** in `SKILL.md`.
